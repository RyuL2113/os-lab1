# ЛР2. Запуск процессов

Выполнила: Ли Анастасия Сангуновна

Библиотека на C для запуска программы в фоне, ожидания её завершения и получения кода возврата.
Работает на Windows (MinGW, WinAPI) и Linux (POSIX). Тестовая утилита `proctest` проверяет библиотеку.

## Структура

```
os-labs/   (ветка lab2)
├── CMakeLists.txt
├── include/proclaunch.h   интерфейс библиотеки
├── src/proclaunch.c       реализация (#ifdef _WIN32 ... #else ... #endif)
├── test/proctest.c        тестовая утилита
├── build.sh, build.cmd
├── .gitignore, .gitattributes
└── .vscode/
```

Функции:

| Функция | Что делает |
|---|---|
| `pl_start(argv, &proc)` | запускает программу и сразу возвращает управление; 0 / -1 |
| `pl_wait(&proc, &code)` | ждёт завершения, отдаёт код возврата; 0 / -1 |
| `pl_poll(&proc, &code)` | проверка без ожидания: 1 - завершился, 0 - работает, -1 - ошибка |

**Linux.** `fork()` + `execvp()` в ребёнке, после неудачного exec - `_exit(127)`. Чтобы родитель узнал
об ошибке exec, перед fork создаётся канал с `FD_CLOEXEC`: при успешном exec он закрывается сам,
при неудаче ребёнок пишет в него errno, и `pl_start` возвращает -1. Ожидание - `waitpid`
(в `pl_poll` с `WNOHANG`), статус разбирается через `WIFEXITED/WEXITSTATUS` и `WIFSIGNALED/WTERMSIG`
(убитый сигналом процесс даёт 128 + номер сигнала).

**Windows.** `CreateProcessA`, аргументы собираются в одну строку в буфере через malloc:
аргумент с пробелами берётся в кавычки, `"` экранируется как `\"`, слеши перед кавычкой удваиваются,
пустая строка передаётся как `""`. Описатель потока закрывается сразу, описатель процесса хранится
в `intptr_t` и закрывается после `GetExitCodeProcess`.

## Сборка и запуск

Linux: `./build.sh`, Windows: `build.cmd`. Или вручную:

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug          # в Windows добавить -G "MinGW Makefiles"
cmake --build build
./build/proctest                                      # build\proctest.exe
```

Утилита запускает сама себя с ключом `--child КОД МС` (поспать и выйти с кодом), поэтому тесты
одинаковые на обеих системах.

| № | Тест | Ожидается |
|---|---|---|
| 1 | ребёнок 1 с, код 42, родитель в цикле `pl_poll` + пауза 100 мс | больше 3 итераций, код 42 |
| 2 | ребёнок 0,3 с, код 7, `pl_wait` | 7 |
| 3 | аргументы `hello "big" world\`, `C:\my dir\`, пустая строка и др. | ребёнок получил их без искажений |
| 4 | `no_such_program_12345` | `pl_start` вернула -1 |
| 5 | код 300 | Linux 44, Windows 300 |

Пример вывода (Linux):

```
[ OK ] 1. родитель работает, пока работает ребёнок; код 42
[ OK ] 2. pl_wait дожидается и возвращает код 7
[ OK ] 3. аргументы с пробелами, кавычками и слешами переданы без искажений
[ OK ] 4. запуск несуществующей программы - ошибка
[ OK ] 5. код возврата 300
```

Дополнительные режимы:

```
proctest --code 123                  ребёнок с заданным кодом, печатает полученный код
proctest --run ls "/no such dir"     запустить любую программу и показать её код
proctest --run no_such_program       ошибка запуска
```

Проверка зомби в Linux (во время работы тестов):

```
./build/proctest & sleep 0.5; ps aux | grep defunct
```

Отладка ребёнка в gdb: перед `run` выполнить `set follow-fork-mode child`.

## Контрольные вопросы

1. В родителе fork возвращает PID ребёнка, в ребёнке 0 (-1 при ошибке). Ребёнок - копия родителя,
   exec заменяет его образ нужной программой.
2. `exit` вызовет atexit-обработчики и сбросит буферы stdio, скопированные от родителя, - вывод
   напечатается второй раз. `_exit` сразу завершает процесс.
3. Зомби - завершившийся процесс, статус которого родитель ещё не забрал через wait. В `ps` у него
   статус `Z` / `<defunct>`. Чтобы не было зомби, для каждого ребёнка вызывается `waitpid`.
4. В POSIX код возврата - младшие 8 бит: 300 mod 256 = 44. После `kill -9` процесс завершается
   сигналом, `WIFSIGNALED` истинно, библиотека вернёт 128 + 9 = 137.
5. Через канал с `FD_CLOEXEC`: при удачном exec канал закрывается и родитель читает 0 байт,
   при неудаче ребёнок пишет errno. Другой способ - `posix_spawnp`.
6. CreateProcess получает одну строку, и ребёнок сам делит её на argv по пробелам, поэтому
   аргумент с пробелом нужно взять в кавычки. Литерал нельзя: CreateProcessA может изменить
   строку, а литерал лежит в памяти только для чтения.
7. `hProcess` и `hThread`. `hThread` не нужен - закрывается сразу, `hProcess` - после получения
   кода возврата, иначе утечка описателей.
8. `STILL_ACTIVE` = 259.
9. Статическая библиотека (.a/.lib) копируется в исполняемый файл при линковке, разделяемая
   (.so/.dll) подгружается при запуске и может использоваться несколькими программами.
   `add_library` объявляет цель-библиотеку, `target_link_libraries` подключает её к программе
   (вместе с include-папками, объявленными как PUBLIC).
10. `extern "C"` отключает декорирование имён в C++, чтобы библиотеку на C можно было вызвать
    из C++. `windows.h` в заголовке нет, чтобы интерфейс был одинаковым для обеих систем и
    не тащил WinAPI в код пользователя - поэтому HANDLE хранится как `intptr_t`.
