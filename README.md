# ЛР3. Общий счётчик

Выполнила: Ли Анастасия Сангуновна

Программа для Windows и Linux на C++17 без сторонних библиотек. Счётчик увеличивается на 1 каждые
300 мс в каждом запущенном экземпляре; число, введённое в любом окне, становится значением счётчика
у всех. Раз в секунду в `lab3.log` пишется время с миллисекундами, PID и счётчик, раз в 3 секунды
запускаются две копии программы. Экземпляров может быть сколько угодно, но в лог пишет и копии
запускает только один — ведущий.

## Как устроено

**Общая память.** Процессы не видят память друг друга, поэтому счётчик лежит в разделяемой памяти:

```cpp
struct SharedData {
    uint32_t magic;       // память уже заполнена
    int32_t  attached;    // сколько процессов подключено
    int64_t  counter;
    int64_t  leader_pid;  // 0 - ведущего нет
    int64_t  leader_beat; // когда ведущий последний раз отмечался
};
```

|              | Linux                                   | Windows                                         |
|--------------|-----------------------------------------|-------------------------------------------------|
| память       | `shm_open` + `ftruncate` + `mmap`       | `CreateFileMappingA` + `MapViewOfFile`          |
| замок        | именованный семафор `sem_open("/lab3_sem")` | именованный мьютекс `CreateMutexA("Local\\lab3_mutex")` |
| удаление     | последний процесс делает `shm_unlink`   | ОС удаляет сама после последнего `CloseHandle`  |

Память открывается и инициализируется под замком (по `magic`), иначе два одновременно запущенных
процесса оба решили бы, что они первые. `std::mutex` не подходит — он работает только между потоками
одного процесса.

**Потоки.** Основной поток читает ввод (`fgets`), второй поток (`std::thread`) — таймер. Таймер
обслуживает три периода (300 мс, 1 с, 3 с); следующий срок считается от расписания, а не от момента
пробуждения, поэтому интервалы в логе не уплывают. Время для расписания — монотонные часы
(`CLOCK_MONOTONIC` / `GetTickCount64`).

**Ведущий.** На каждом тике под замком процесс прибавляет 1 и смотрит на `leader_pid`: если это он сам —
обновляет `leader_beat`, если места нет или ведущий не отмечался больше 1 с — занимает место.
При выходе ведущий пишет `leader_pid = 0`, и роль сразу переходит к другому. Если ведущего убить,
через секунду его место займёт другой экземпляр.

**Копии.** Это та же программа с ключом `--copy1` / `--copy2`, запускается через `pl_start` из ЛР2.
Путь к себе берётся через `/proc/self/exe` / `GetModuleFileNameA`, а не из `argv[0]`.
Копия 1 прибавляет 10 и выходит, копия 2 умножает на 2, через 2 с делит на 2 и выходит (замок на время
паузы не держит). Перед запуском прошлая копия проверяется через `pl_poll`: если она ещё работает,
новая не запускается и в лог пишется сообщение. Завершившиеся копии забираются на каждом тике,
так что зомби не остаются.

**Выход.** `q` или Ctrl+C. В Linux обработчик `SIGINT` только ставит флаг; на время создания потока
таймера сигнал блокируется, чтобы приходил в основной поток, `sigaction` без `SA_RESTART` — `fgets`
прерывается. В Windows обработчик `SetConsoleCtrlHandler` ставит флаг и закрывает stdin. Дальше:
остановить таймер, освободить место ведущего, дождаться копий, `exit` в лог, отключиться от памяти.

## Сборка и запуск

Linux: `./build.sh`, Windows: `build.cmd`. Или вручную:

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug          # в Windows добавить -G "MinGW Makefiles"
cmake --build build
./build/lab3                                          # build\lab3.exe
```

Несколько экземпляров запускать в разных терминалах из одной папки — `lab3.log` создаётся в текущей.
Смотреть лог: `tail -f lab3.log` (Linux), `powershell Get-Content lab3.log -Wait` (Windows).

## Проверка

1. Один экземпляр: раз в 1 с `counter = ...`, раз в 3 с `start/exit (copy 1)` и `start/exit (copy 2)`.
2. Два-три экземпляра: строка со счётчиком всё равно одна в секунду, счётчик растёт быстрее,
   число, введённое в любом окне, видят все.
3. `q` или Ctrl+C в окне ведущего — в логе `became the leader` от другого PID.
4. Пропуск копии. Linux: сразу после `start (copy 2)` выполнить `kill -STOP <pid>`, через 3 с в логе
   `copy 2 (pid ...) is still running, not started`, потом `kill -CONT <pid>`.
   Windows: Монитор ресурсов → ЦП → правый клик по процессу копии → «Приостановить процесс».
5. Linux, после выхода всех экземпляров: `ls /dev/shm` — нет `lab3_shm` (`sem.lab3_sem` остаётся
   специально, см. ниже), `ps aux | grep defunct` — пусто.

Если экземпляр убить через `kill -9`, он не успевает уменьшить `attached`, и общая память после выхода
остальных остаётся — новый запуск продолжит со старого значения. Тогда: `rm /dev/shm/lab3_shm`.
